# 源码公开与软件分发

本项目当前建议先分享源码与 [Install.command 构建安装步骤](构建与安装.md)。添加许可证并不表示安装包已经适合广泛分发，也不构成安全或法律合规认证。

## 许可证路线

项目自有代码、说明及原创图标采用 **AGPL-3.0-only**，完整条款见根目录 `LICENSE`，授权范围与声明见 `NOTICE`。这是配合当前 PyMuPDF/MuPDF 依赖采用的开源路线；不是为第三方组件重新授权。

- AGPL 允许使用、修改、分发和商业用途，并非“禁止商用”。
- 分发受该许可覆盖的软件或修改版时，要按条款保留许可与版权声明，并提供对应的可修改源码和构建材料。
- 如果把修改后的受许可程序提供为网络服务，AGPL 第 13 条还涉及向远程交互用户提供对应源码的机会。适用范围以许可全文和具体整合方式为准。
- 发布二进制时，必须对应实际发布版本提供源码，不能只链接到一个接收者无法访问的私有仓库。
- 单独加一份 MIT 许可证、免费提供软件，或者让前端通过子进程调用后端，都不应被当作已解决第三方许可义务的依据。
- 闭源销售、嵌入其他产品或改变分发模式时，应重新核查整合方式和全部依赖；可能需要 Artifex 商业授权或更换相关组件。若准备商业发行，建议请熟悉开源许可的人复核具体方案。

`licenses/third-party/` 保留当前锁定 Python 包随安装分发的版权/许可原文。这个目录及其 manifest 是可核对的材料清单，不是对全部嵌入原生库、字体和系统组件的完整合规认证。

## 当前 `.app` 为什么不是通用安装包

1. 开发构建的 `Info.plist` 包含绝对项目路径。`Install.command` 安装版已移除该字段，改为当前用户的运行环境 ID，因此可删除下载源码；但仍依赖本机基础 Python 和该用户运行环境，移动到其他电脑不保证运行。
2. 当前使用 ad-hoc 本机签名，没有 Developer ID、Hardened Runtime 发行验证或 Apple 公证。用户从互联网下载后可能受到 Gatekeeper 拦截。
3. Python、LibreOffice 和系统框架没有完整打入应用。首次源码构建还需 Python 与 Apple 编译工具。不能把本机 Codex 运行环境目录直接复制进去并假定允许再分发。
4. PDF、Office、图像解析依赖均可能存在漏洞，且当前 Python/Office 处理没有强沙箱。27 组功能测试通过不等于不存在安全漏洞。

发布给普通用户前，应在干净的目标 Mac 上验证独立安装、架构、最低系统版本、依赖发现、字体、取消和文件权限。按实际内容整理第三方许可、必要的对应源码、来源与校验值；按 Apple 文档完成适用的签名/公证流程。不要要求用户关闭全局 Gatekeeper 来绕过发行问题。

本地构建会携带 `Contents/Resources/Legal/`：项目许可证、版权说明、第三方材料、分发说明和源码版本信息。`SOURCE_INFO.json` 标识构建时的提交及工作区是否有未提交修改；有未提交修改的构建不能被宣称与该提交的公开源码完全一致。

## 日常维护与风险

- 使用锁定版本构建，但锁定并不证明依赖没有漏洞。升级前查看上游安全通告，并复核测试及许可变化。
- 保留“先备份、复核转换结果”的使用说明。版式、OCR、表格提取、脱敏和 PDF/A 均可能有误差；不要承诺法律签名效力或认证过的归档合规。
- 保留安全报告入口说明，公开反馈只使用合成样例；不要让用户上传真实机密文件来复现问题。
- `AGENTS.md` 建议保留：它帮助 AI 工具遵循项目规则，但不是 GitHub 强制文件、开源许可证、访问控制或免责文件。
